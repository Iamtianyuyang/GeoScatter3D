# GeoScatter3D 平板适配 PRD（简单版）

## 1. 项目信息

- **Language**: 中文
- **Programming Language**: Flutter（Dart），沿用现有 `ui_flutter/` 工程与设计令牌体系（Gs3dTokens / Gs3dType / Gs3dMotion / Gs3dDark / Gs3dA11y，Apple HIG 风格 + `widgets/fluid.dart` 弹簧组件库）
- **Project Name**: `geo_scatter_3d_tablet`
- **原始需求复述**：
  > "这是做的平板和电脑的应用，需要符合平板的操作，也要在平板模拟器上测试。现在开始在平板模拟器上进行重新设计 UI，接入所有核心功能，然后在平板模拟器上进行测试。"
- **测试环境事实**：开发机 Windows；已装 Android Emulator，AVD `Pixel_10_Pro_Fold`（折叠屏、内屏平板级尺寸，作为本阶段"平板模拟器"）与 `Pixel_8a`（辅助小屏验证）。原生引擎仅有 `gs3d_ffi.dll`（Windows），Android 需 NDK 交叉编译且引擎依赖 GLFW（不支持 Android），**本阶段不做引擎安卓移植**。

## 2. 能力边界（本阶段裁决，必须显式遵守架构红线）

| 能力 | 本阶段状态 | 依据 |
| --- | --- | --- |
| 平板自适应 UI（响应式断点、触控手势、抽屉/rail 形态） | **P0，模拟器上全量开发与验证** | 纯 Flutter 层，不触碰 C-ABI |
| 45 项核心动作在平板 UI 上全部"可达" | **P0** | 见 §5 验收口径：纯 UI 动作可直接执行；依赖引擎的动作必须经 R3 显式降级路径触达并报错，而非隐藏 |
| 平板模拟器实测（安装、操作、截图留存） | **P0** | 遵守 R5：截屏走 RepaintBoundary 内存回读，禁止 OS 级截屏 |
| 引擎安卓移植（NDK 交叉编译 `libgs3d_ffi.so`、去 GLFW 化） | **P2 / 后续阶段** | 工程量大且非 UI 迭代范围；GLFW 不支持 Android，需引入平台窗口抽象层，不是本阶段能顺带完成 |
| 引擎在安卓上的行为 | **显式降级报错（P0 的组成部分）** | R3：engine 不可用必须显式报错，不得静默假装可用，更不得用 Dart 软件点云预览冒充视口 |

## 3. 产品目标

1. **一套代码双形态**：GeoScatter3D 在桌面（键鼠优先）与平板（触控优先）上共用同一 Flutter 代码与设计令牌体系，通过响应式断点自动切换布局与交互范式，无需用户感知"缩水的移植版"。
2. **核心功能零缺失可达**：现有 45 项原子动作（welcome.* / viewport.* / leftDock.* / rightDock.* / layout.* / command palette）在平板 UI 上 100% 有入口可达，触控操作完全替代键鼠假设。
3. **模拟器可验证的交付**：在 `Pixel_10_Pro_Fold` 平板模拟器上完成全量 UI 实测并留存证据（widget test + RepaintBoundary 截图），`flutter analyze` 0 告警、`flutter test` 全绿、工作树 clean（R4）。

## 4. 用户故事

1. 作为**平板用户**，我想在折叠屏平板内屏上打开应用后看到为触控重新组织的工作台布局（可折叠抽屉 + 触控工具条），以便不用键鼠也能完成打开/浏览/测量/调参全流程。
2. 作为**平板用户**，我想用单指拖拽旋转、双指平移、双指捏合缩放来操作三维视口，以便获得与桌面"右键/中键平移、滚轮缩放"等价的操作体验。
3. 作为**平板用户**，当引擎在安卓上不可用时，我想看到明确的错误提示与引导（而非假视口或静默失败），以便知道哪些功能需回到桌面版使用。
4. 作为**平板用户**，我想通过拇指可达的底部动作条/命令面板按钮访问全部命令，以便在无键盘设备上也能触发快捷键对应的全部功能。
5. 作为**开发者/测试者**，我想在 widget test 中以 1192×820（折叠内屏竖向）与 2208×1840（内屏横向）等平板逻辑分辨率运行现有 60+ 用例及新增平板断言，以便在 CI 上回归平板布局而不依赖模拟器。

## 5. 技术规范

### 5.1 Requirements Pool

**P0（Must have）**

- **响应式断点策略**（单一事实源，接入现有 `Gs3dTokens`，禁止散落魔法数字）：
  - `compact < 600`（手机，仅回归验证不新增）：现有桌面布局退化为窄屏堆叠；
  - `tablet 600–1100`：**本阶段主战场**。左右停靠面板改为**可折叠抽屉**（默认收起，边缘把手唤出），顶栏菜单收敛为触控工具条，底部新增拇指区动作条；
  - `expanded > 1100`：桌面布局保持现状（floatingDock / analysisRail / standard 三套布局照旧），平板大屏横向也可命中此档并复用 rail 形态。
  - 断点依据窗口宽度 + 设备形态判定；foldable 内外屏切换、铰链折叠姿态（half-open 分栏）纳入 P1。
- **触控手势替换键鼠假设**：
  - 单指拖拽 = 旋转（视口主操作）；双指拖拽 = 平移（等价原中键）；双指捏合 = 缩放（等价滚轮）；
  - hover 态在触屏设备上降级：所有仅 hover 暴露的提示/按钮改为长按提示（tooltip on long-press）或常显；
  - 右键菜单改为长按菜单（context menu via long-press）。
- **触控目标尺寸**：现有 `Gs3dTokens.hitTarget = 28` 偏小，新增 `hitTargetTouch = 48`（Material 下限，同时满足 Apple HIG 44pt），平板档位下全部可交互控件应用触控命中区（视觉尺寸可小于命中区，但命中区 ≥48）。
- **命令面板按钮化**：顶栏/动作条新增常驻"命令"按钮唤起命令面板（等价 Ctrl+K/P 入口），保证无键盘时全部命令可达；Ctrl+N/O/B 等快捷键在物理键盘存在时继续生效。
- **对话框平板形态**：compact/tablet 档位下对话框改用**底部 sheet**（拇指可达），expanded 档位保持居中模态。
- **引擎不可用的显式降级（R3 合规）**：安卓/模拟器上 engine FFI 加载失败时，欢迎页与视口区显示明确错误卡片（"渲染内核在本平台不可用"），45 项动作中**依赖引擎的动作可点击但返回显式错误反馈**；严禁 Dart 软件点云预览、严禁静默假可用、严禁直接隐藏入口导致"功能缺失"与"引擎不可用"混淆。
- **平板模拟器实测**：`Pixel_10_Pro_Fold` 上完成安装、全功能走查、截图留存（RepaintBoundary 内存回读，R5）；退出流程走 shutdown（R5）。
- **测试基线不回退**：`flutter analyze` 0 告警；`flutter test` 原有 60 通过用例全绿，新增平板尺寸 widget test；C++ 侧 ctest 43/43 不受影响。

**P1（Should have）**

- foldable 姿态适配：内/外屏切换时布局平滑过渡（`MediaQuery` displayFeatures）；铰链 half-open 姿态下双栏分屏（左侧视口 + 右侧统计/渲染参数）。
- 平板档位下的 dock 拖拽重排与记忆布局（`layout.*` 动作在平板形态下的等价实现）。
- 无障碍复核：`Gs3dA11y` 在触控形态下的语义标签与焦点顺序补全。
- 手写笔/压力事件预留（仅 API 层预留，不做功能承诺）。

**P2（Nice to have / 后续阶段）**

- **引擎安卓移植**：NDK 交叉编译 `libgs3d_ffi.so`、剥离 GLFW 依赖引入平台窗口/surface 抽象层（如 Vulkan Android WSI + Flutter 外接纹理）。理由：工程量大、风险高（GLFW 不支持 Android 需架构级改造），与"平板 UI 重新设计"正交，应独立立项。
- 桌面/平板状态云同步、多窗口（desktop multi-window）。

### 5.2 UI 设计草案（平板形态布局描述）

```
┌────────────────────────────────────────────┐
│ 顶栏：品牌 + 视图切换 + [命令按钮] [布局按钮] │  ← 高度≥56，触控目标≥48
├──────────┬─────────────────────┬───────────┤
│ 左抽屉   │                     │  右抽屉   │
│ (收起态: │    三维视口          │ (收起态:  │
│ 边缘把手)│  (engine 卡片或     │ 边缘把手) │
│          │   显式降级错误卡)    │           │
├──────────┴─────────────────────┴───────────┤
│ 底部拇指区动作条：视口工具 · 测量 · 统计 · …  │  ← 高度≥64，主要动作位于拇指弧
└────────────────────────────────────────────┘
```

- 左右面板：tablet 档默认收起为边缘把手（宽 24），点按滑出为宽 320–400 的浮层抽屉（Glass 材质复用 `Gs3dGlass`），不遮挡视口主区；expanded 档保留常驻 rail。
- 对话框/文件选择/确认操作：tablet 及以下档用底部 sheet（拖拽把手可下滑关闭）；expanded 保持居中模态。
- 命令面板：保持现有面板样式，入口按钮化 + 长按顶栏品牌区亦可唤起。
- 视口手势提示：首次进入显示一次性手势引导卡（单指/双指图示），符合 `Gs3dMotion` 弹簧入场。
- 全部新组件只用现有令牌与 `widgets/fluid.dart` 弹簧组件，不引入第二套视觉体系。

### 5.3 "接入所有核心功能"验收口径（45 项动作分类）

| 类别 | 动作组 | 平板模拟器上的验收方式 |
| --- | --- | --- |
| 纯 UI 动作（引擎无关，**可直接执行并验证**） | `welcome.*` 打开/新建/示例、`layout.*` 三套布局切换、命令面板开关、面板开合、主题/无障碍设置 | 真实执行 + RepaintBoundary 截图比对 |
| 依赖引擎的视口动作 | `viewport.*` 相机与工具（旋转/平移/缩放/选择等） | 入口可达，点击后验证 R3 显式降级错误反馈（不得假渲染） |
| 依赖引擎的数据面板动作 | `leftDock.*` 测量与统计、`rightDock.*` 渲染参数 | 入口可达，参数面板 UI 正常展示与编辑，应用/执行链路验证显式降级反馈 |

→ 验收 = "可达性 100%" + "纯 UI 类执行 100%" + "引擎依赖类降级反馈 100% 正确"，三者均通过方可验收。

### 5.4 测试策略

1. **Widget test（CI 层）**：现有用例补跑平板 surface（`1192×820`、`2208×1840` 逻辑分辨率 + `folded` 外屏尺寸），断言：断点切换正确、抽屉默认收起/可唤出、触控命中区 ≥48、命令按钮存在、底部动作条可达性。新增"引擎加载失败 → 显式降级卡片"用例。
2. **45 项动作路由用例**：在平板 surface 下复跑，确保无动作因布局重构而丢失路由。
3. **模拟器实测（验收层）**：`Pixel_10_Pro_Fold` 清单——安装启动 / 欢迎页 / 每类动作各抽全量入口遍历 / 手势操作 / 内外屏与折叠姿态切换 / 退出 shutdown / 全程无异常日志。截图统一走 RepaintBoundary 内存回读留存至 `tmp/`（R4/R5），测试自清理。

### 5.5 架构红线遵循

全部改动限于 Flutter UI 层：状态仍收敛 `GeoScatter3dService`，组件只读投影 + 事件发射（R1）；不经 C-ABI 引入任何图形句柄穿透，`executeAction` 面不变（R2）；不实现任何软件渲染替代（R3）；产物收敛 `tmp/`（R4）；退出 shutdown、无 OS 截屏（R5）。

## 6. 待确认问题（需用户拍板）

1. **平板主目标设备**：本阶段仅以 `Pixel_10_Pro_Fold` 内屏为验收基准，还是需要同时覆盖 iPad 类固定平板（如 iPad Pro 11"）的分辨率组合？影响 widget test surface 矩阵。
2. **引擎依赖动作的降级表现**：点击依赖引擎的动作时，用户希望"点击 → 弹错误提示"，还是"入口置灰 + 旁注说明引擎不可用"？（PRD 默认前者：保持可达 + 显式错误，符合 R3 字面）
3. **视口主手势映射**：单指拖拽默认"旋转"是否符合预期？部分点云工具习惯单指=平移。需要用户确认主操作习惯（PRD 默认单指=旋转）。
4. **折叠姿态分屏**：铰链 half-open 双栏布局放在本阶段（升 P0）还是后续（维持 P1）？
5. **引擎安卓移植立项时间**：P2 是否需要在下一迭代明确排期（涉及 NDK + 去 GLFW 化的架构改造），还是待平板 UI 验收后再议？
