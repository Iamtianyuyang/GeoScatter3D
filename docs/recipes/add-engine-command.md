# 配方：加一个引擎命令

命令 = Dart 发意图，引擎执行，结果通过快照或事件回到 Dart。

## 步骤

1. **选通道**：
   - 立即完成的小操作（相机输入、点大小、配色、背景）→ 同步命令，进结构体。
   - 耗时操作（开包、预处理、LOD、导出）→ 异步命令，返回任务号。
   - 低频结构化配置（配置文件、对话框、诊断）→ JSON 通道
     `gs3d_engine_request`，带 `"v": 1`，字段只增不改。
2. **定类型**（`engine/abi/`）：在 `gs3d_command` 尾部追加 op 与参数块，遵守规则二。
   参数只放 POD 与"调用期间有效"的 `const char*`；异步命令要求引擎**深拷贝**，
   因为返回后指针就失效。
3. **镜像**（`app/lib/ffi/`）：同名同布局的 `Struct`，并在
   `app/test/ffi/abi_layout_test.dart` 断言尺寸与偏移。
4. **Dart 封装**（`app/lib/ffi/geoscatter3d_service.dart`）：语义命名的方法，只做
   参数校验与 `submit`，不做业务判断；异步命令把返回的任务号存进快照模型。
5. **引擎实现**：校验放 `engine/session/`（要 GPU 的放 `engine/render/`）。
   校验失败返回负错误码并写入快照的 `last_error`；不许抛异常穿过 ABI。
6. **结果回流**：
   - 一次性结果 → 写进 `gs3d_state`，下一次 `poll_state` 读出；
   - 长任务 → 任务表里写阶段、进度、可取消，结束发 `GS3D_WAKE_TASK` 或
     `GS3D_WAKE_ERROR`。终态保留到被读取一次，防止 Dart 错过。
7. **线程**：命令在调用线程只做校验与深拷贝，执行在渲染线程（GPU 相关）或工作池
   （数据相关）。工作线程要改渲染状态，必须投递回渲染线程，不许直接写。

## 测试（三件事缺一不可）

- 正常路径：提交后用 `poll_state` 读到预期字段；
- 非法参数：错误码 + `last_error` 有内容，进程不崩；
- 前置条件不满足（没打开数据集 / 没 GPU）：明确报错，不是静默无事发生；
- 异步命令额外一条：立即返回任务号、进度单调、取消后进入终态、终态只被读取一次。

## 反面例子

命令处理函数返回 `std::string` 的 `data()` 给 Dart，或者异步命令保存了 `const char*`
参数。后果：调用返回后指针失效，Dart 读到随机内存，只在特定分配顺序下崩溃——最
难查的一类 bug。

## 检查

- [ ] 慢操作是异步的，返回任务号
- [ ] 参数已深拷贝，引擎没保存调用方指针
- [ ] Dart 结构体有尺寸断言
- [ ] 四条测试都在，失败用例断言的是具体错误码
