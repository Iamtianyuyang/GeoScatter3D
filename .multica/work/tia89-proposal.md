# TIA-89 前端重设计方案提案(诊断 + 方向,等人类确认)

基于 checkout `1f0eb84` 代码阅读、TIA-88 运行截图(`main-viewer.png` / `main-viewer2.png`,1384×865,碳蓝浅色主题实拍)与 TIA-84 审查结论。只出方案,未改任何代码。

---

## 一、现状诊断

### 1.1 布局结构:三套布局方案并行,每个都只做了一半

- `UiRoot.cpp:842-870` 按 `UiLayoutMode` 分派到**三套互相独立的布局实现**:方案 A 工作台(`UiRoot.cpp`,1207 行)、方案 B 悬浮 Dock(`FloatingDockUi.cpp`,3633 行)、方案 C 暗色分析舱(`AnalysisRailUi.cpp`,1878 行)。
- 「视图 → 布局」菜单把架构决策直接暴露给用户(`UiRoot.cpp:954-962`「方案 A · 专业工作台 / 方案 B · 悬浮 Dock / 方案 C · 暗色分析舱」)。对用户而言这是「三个界面」,且 B/C 的面板卡片/抽屉状态(DockUiState / AnalysisRailState)与 A 完全不通、也都不持久化(TIA-84 问题 1/6 同源)。
- 默认面板配置偏「开发者模式」:性能面板默认开启(`AppState.hpp:164`),瓦片/细节层级等调试面板默认在左侧停靠区占位;右侧 属性/性能/日志 三面板叠 tab。
- 工作窗口模型概念叠加:视图标签、工作窗口、独立原生窗口三层(`WorkspaceManager.cpp:225-241` 关最后一个视图标签会连带关闭整个工作窗口,已确认容易惊吓用户,TIA-84 问题 8)。

### 1.2 视觉层级:扁平浅色 + 弱对比,层次感不足

- 截图实测(`main-viewer.png`):整体平均亮度 ~155-162,上方 ~40% 为浅色面板/工具栏区,下方 ~55% 为深色视口(0x1A1D23);左侧一条 ~115px 深色条带为导航图暗色占位(`NavigationMapPanel.cpp:43-44`)。即「浅色 UI + 深色画布」的割裂感。
- 碳蓝主题(`Theme.cpp:34-84`)所有表面都是近白灰阶(F5F7FA 底 / FBFCFD surface / F4F7FA frame),面板之间靠 1px 边框(alpha 0.62)与 8%~25% alpha 的 accent 区分,层次弱、扫描性差。
- 状态栏是单行密集文本(`UiRoot.cpp:1126`「%.1f FPS … %llu 点 GPU %.1f MB %s」),无分段、无图标、无主次。
- 工具条是纯文本 chip 行(操作/添加视图/截图/测量…,`UiRoot.cpp:280-300`),52px 高(`UiRoot.cpp:104`)内容稀疏,右侧还塞一条数据集路径;「添加视图/截图/测量」这些**动作**与「联动」这类**状态开关**混在同一行,无分组。

### 1.3 信息密度:面板堆叠 + 死面板 + 首屏割裂

- 属性面板 347 行单列滚动(点大小/形状/着色/色标/值域/高度缩放等 20+ 控件),无分组折叠、无搜索(`RenderSettingsPanel.cpp`)。
- 导航图/测量/区域统计三个辅助面板默认全开(`AppState.hpp:165-167`),与项目面板挤占左侧停靠区。
- 「日志」面板是死面板:`DebugLogState` 只有 3 条初始化文本(`AppState.hpp:251-257`),`AuxiliaryPanels.cpp:150-152` 只读展示,全仓无写入方(TIA-84 问题 6)。
- 欢迎页是 2628 行完全自绘的 hero(`WelcomePage.cpp`),卡片/图标全部手绘(如 `WelcomePage.cpp:201-248` draw_folder_icon/draw_plus_icon),与工作台的 ImGui 原生控件语言割裂——首屏印象与主界面不像同一个产品。

### 1.4 交互一致性:快捷键门控不一致、配置无入口、反馈缺位

- Ctrl+O / Ctrl+N 无文本输入门控,而 M / C 键有(`ViewportCanvas.cpp:655-666` vs `:674`/`:1307`;TIA-84 问题 5)。
- camera/controller 参数(`fov_y`、`rotate_speed` 等)全无 UI 入口,渲染设置改完即失(`AppConfigViewerToml.cpp:67-105`;TIA-84 问题 4)。
- 主题/布局切换不回写(`viewer.toml:25-28` 注释明示),重启回默认。
- 字体栈仅 NotoSansCJKsc Regular/Bold(`assets/fonts/`,`ImGuiLayer.cpp:29-33` 14/13/12px),无图标字体、无数值等宽字体;所有图标手绘。
- 操作可发现性弱:测量/框选/统计/联动全靠文本 chip;帮助菜单只有两条 bullet(`UiRoot.cpp:1057-1062`)。

### 1.5 与 TIA-84 审查结论的呼应

TIA-84 确认架构分层清晰、交互状态机成熟、无严重问题,缺口集中在「配置一致性 + 死面板 + 布局持久化」。本提案**不重复**那些修复项(TIA-90 已立项),但重设计必须与修复方向兼容:布局持久化生效后,「用户自定义布局可信赖」才成立,重设计的默认布局才有意义。

## 二、设计方向(3 个候选)

### 方向 A ·「碳蓝工作台 2.0」—— 收敛单工作台 + 现代化打磨(推荐)

**布局骨架**:放弃三方案并存,以方案 A 为唯一骨架演进。
- 顶栏(约 44px):左侧应用标识 + 文件/视图/窗口/帮助合并为紧凑菜单;中部全局工具(打开/截图/添加视图/测量/联动,图标+文字);右侧数据路径徽标。取代现在的「菜单栏 + 52px 工具条」两层。
- 左侧可折叠面板区:项目/测量/区域统计 三个业务 tab + 底部导航图(可收起);瓦片/细节层级移入「调试」分组,默认关闭。
- 右侧可折叠面板区:属性(分组折叠化)+ 性能(默认关闭);日志面板下线。
- 中央视口区最大化;底部状态条改 26px 分段信息带:FPS/帧时 | 可见点 | GPU 驻留 | 数据就绪态,每段带图标与弱分隔。
- 视口 HUD 四角分区(基于现有 overlay 重排):左上相机/坐标 badge、右上导航球、左下比例尺、右下数据 badge(`ViewportCanvas.cpp:624-651` draw_viewport_overlay 现有元素重排,不改渲染)。

**配色/主题策略**:保留 TOML `theme=` 机制与 `ThemeTokens` 结构,但把 token 重构成语义层级(bg / surface / raised / border / text×3 级),碳蓝、石墨两套重校对比度,新增「高对比」浅色变体(面向测绘专业场景)。**主题与布局选择持久化到用户偏好文件**(与 `src/app/UserPreferences.cpp` 的 preferences.toml 同机制,不回写 viewer.toml,兼容 TIA-90 方向)。

**字体/间距/层级**:引入图标字体子集(Material Symbols 或等价开源集)替换全部手绘图标;数值/坐标用等宽字体;字号层级 12/13/14/16 + 面板标题;现有 `LayoutMetrics` 常量(`UiRoot.cpp:98-109`)扩展为统一间距 token。

**关键交互改进**:
- 相机导航:滚轮缩放改指数曲线、双击视口复位相机、导航球支持点按平面锁定视角。
- 面板管理:统一「面板注册表」(一个 enum + 一组打开/关闭/停靠命令),`Ctrl+P` 面板命令面板,替代现在散在「窗口」菜单里的 10 个 checkbox。
- 多视图:视图标签栏加「+」;关闭最后一个视图标签时保留空工作窗口并可随时放回视图(TIA-84 问题 8 方向)。
- 测量/框选:工具条按钮激活态高亮 + 快捷键提示 tooltip;测量面板与视口 HUD 联动。
- 快捷键:`?` 打开快捷键总览 overlay;补齐 Ctrl+O/N 门控。

**改动范围(文件级)**:
- 重写:`src/ui/UiRoot.cpp`(顶栏/状态条/面板编排)、`src/ui/Theme.cpp` + `include/ui/UiPalette.hpp`(token 化)、`src/ui/Widgets.cpp` + `include/ui/Widgets.hpp`(图标按钮/分组/分段状态条控件)。
- 调整:`src/ui/ViewportCanvas.cpp`(HUD 分区)、`src/ui/DatasetPanel.cpp` / `RenderSettingsPanel.cpp`(分组折叠)、`src/ui/AuxiliaryPanels.cpp`(日志下线)、`include/app/AppState.hpp`(PanelVisibility 默认值 + 偏好键)、`src/app/ViewerAppGuiCommands.cpp`(新命令透传)。
- 冻结/删除:`src/ui/FloatingDockUi.cpp`、`src/ui/AnalysisRailUi.cpp` 用户入口移除(代码先保留,随后续清理删除并同步 `UiRoot.cpp:842-870` 分派)。
- 新增:`include/ui/PanelRegistry.hpp`、图标字体合并(`src/gui/ImGuiLayer.cpp` 字体表)、偏好文件主题/布局键。

**工作量与风险**:约 5-7 人日(含测试更新);风险中——面板编排重写影响面大,但 `ui → UiActions → app` 分层与 AppState 状态模型不动,现有 37 项测试可作回归基线。

### 方向 B ·「深色数据舱」—— 沉浸暗色 + 图标导航

**布局骨架**:以方案 C 分析舱(`AnalysisRailUi.cpp`)为基座演进:默认深色;左侧 48px 窄图标导航栏(数据/外观/测量/视图/系统),点击弹出抽屉,失焦自动收起;中央视口占 ~90% 屏面;右上 HUD 胶囊;底部 22px 细状态条。
**配色/主题**:deep-graphite 演进为唯一默认主题(暗色 + 琥珀/蓝 accent 两变体),同样走 token 化。
**关键交互**:键盘优先、抽屉式命令、视口最大化;代价是长属性列表在抽屉内体验差,信息密度承载能力弱于 A。
**改动范围**:重写 `AnalysisRailUi.cpp` 主体 + 继承方向 A 的 token 化/字体/偏好落地(需要 A 的前置工作)。
**工作量与风险**:约 8-10 人日;风险高——沉浸式布局与「属性面板 20+ 控件」的专业编辑需求天然冲突,且 B 的用户群(测绘/地信)更依赖直接可见的信息层级。

### 方向 C ·「轻量打磨」—— 保留三布局,统一设计系统

**布局骨架**:完全不动 A/B/C 三方案与默认面板配置。
**改动范围**:仅 token 化主题、图标字体、状态栏分段、日志面板下线、快捷键提示 overlay(`Theme.cpp` / `Widgets.cpp` / `AuxiliaryPanels.cpp` / `UiRoot.cpp` 样式段)。
**工作量与风险**:约 2-3 人日;风险低,但不解决「三界面并存 + 开发者面板默认可见 + 首屏割裂」这三个最可能让用户不满的结构性根因,收益有限。

## 三、推荐方案

**推荐方向 A**,理由:

1. **直击根因**:用户不满最可能来自「三个界面并存、默认开发者面板、浅色扁平无层次、首屏与工作台割裂」——A 全部覆盖;B 是风格偏好,可在 A 落地后作为暗色主题变体叠加;C 不解决结构问题。
2. **工程上最稳**:方案 A 已有成熟代码与测试基底(交互状态机、命令队列、37 项测试),收敛掉 B/C 反而**减少**了后续每个 UI 改动 x3 的维护面;与 TIA-84「架构好、一致性差」的结论同向。
3. **兼容既定修复**:布局持久化(TIA-90)是 A 的「用户布局可信赖」前提,方向一致;偏好文件持久化与 TIA-90 的运行期设置持久化共用同一机制。
4. **不破架构**:全程保持 `ui 产出 UiActions 命令队列、AppState 持有 UI 状态` 的分层,不引入新依赖(图标字体可用 Open 子集,不新增第三方库)。

## 四、验收建议(供确认后实施任务 TIA-92 使用)

1. **截图对比**:同一 50M 数据集、同一相机位,改前/改后主窗口截图(浅色主题)并排对比,检查:顶栏与状态条层级、面板默认开关(性能/调试面板默认隐藏)、视口 HUD 四角分区。
2. **交互清单走查**(逐项人工):打开项目 → 50M 加载 → 旋转/平移/缩放 → 测量 3 点 → 框选统计 → 添加视图 → 拖拽停靠 → **重启后布局保留** → 主题切换后**重启保留** → `?` 快捷键总览弹出 → Ctrl+O/N 在搜索框聚焦时不误触发 → 日志面板不再出现在窗口菜单。
3. **技术验收**:ctest 全绿(既有 37 项 + 新增面板注册表/偏好键测试);无新增 Vulkan validation 违规;移除 B/C 入口后无悬空引用;文件行数预算(工程护栏)不超。
4. **回归风险点**:布局重建触发条件(`UiRoot.cpp:678-686`)与 TIA-90 的 ini 持久化修复合并验证;面板默认值变更对既有单测(`ViewerAppStateInitializationTests` 等)的影响逐项核对。
